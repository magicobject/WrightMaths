Functions

A function is a rule that turns each input into one output. This page names the kinds of rule, and asks which inputs a rule can take and which outputs it can give. You combine two functions into one, with the second rule applied to the result of the first. You undo a function with its inverse, and you see why the graph of an inverse is a reflection in the line {m:y=x}. At the end you use functions to model a real situation, and you say where the model stops being sensible.

Where you will use this: in Sequences, in Parametric equations and in Locating roots, which all start from a function. The inverse of a function gives you the inverse trigonometric functions. Any question that says “find the range”, “find {m:fg(x)}” or “find {m:f^(-1)(x)}” uses the rules on this page.

1. Mappings and functions

A {term:mapping} sends each input to one or more outputs. You can draw one as a {term:mapping-diagram|mapping diagram}: the inputs in one column, the outputs in the other, and an arrow from each input to each of its outputs. A {term:function} is a mapping with one extra rule. Each input has exactly one output.

You write a function as {m:f(x)=x^2}, or as {m:f:~x~mapsto~x^2}, read “f maps x to x squared”. The input is x and the output is {m:f(x)}.

The picture above is a {term:many-to-one} function: at least two inputs give the same output. A {term:one-to-one} function is the other kind. Each output comes from exactly one input. For example {m:f(x)=2x+1} is one-to-one.

Key idea: a function gives exactly one output for each input. Two inputs may share an output, but one input may not have two outputs.

  • A {term:function} has exactly one output for each input in its domain. In a mapping diagram, exactly one arrow leaves each input.
  • A {term:one-to-one} function has each output coming from exactly one input. A {term:many-to-one} function has at least two inputs sharing an output.
  • A mapping where one input has two or more outputs is not a function.
  • To show that a function is many-to-one, find two different inputs with the same output. One pair is enough.
  • The notation {m:f(x)} does not mean f times x. It means the output of f when the input is x.

2. Domain and range

The {term:domain} of a function is the set of inputs it is allowed to take. The {term:range} is the set of outputs it gives. Sometimes a question states the domain, as in {m:f(x)=x^2-4x+5} for {m:0 <= x <= 3}. That is a {term:restricted-domain|restricted domain}. If the question gives a formula and no domain, you use the {term:largest-domain|largest possible domain}: every {term:real-number|real number} that the formula can accept.

In this topic, a formula can break in three ways. You cannot divide by 0. You cannot take the square root of a negative number. And {m:ln x} needs a positive x (see Exponentials and logarithms). The largest domain leaves out every x that causes one of these.

Key idea: the domain is a set of x-values and the range is a set of y-values. When no domain is given, take the largest one the formula allows.

  • Largest domain: leave out the x that make a denominator 0. Under a square root, the expression must be at least 0, written {m:>= 0}. Inside {m:ln}, the expression must be greater than 0. If a formula has several of these, all the conditions hold at the same time.
  • Write a domain with x, as in {m:x >= 1}, {m:x != 2} or {m:0 <= x <= 3}. Write a range with {m:f(x)}, as in {m:f(x) >= 0}.
  • To find the range, look at the graph for the lowest and highest outputs, or work them out. For a restricted domain, check the end points and any turning point between them.
  • A different domain gives a different function, and it may have a different range.

Worked example: a fraction

The function f is given by {m:f(x)=frac(1, x-2)}. Find the largest possible domain and the range.

  1. The bottom {m:x-2} is 0 when {m:x=2}. So the domain is {m:x != 2}.
  2. The top is 1, so the fraction is never 0. The output 0 is not in the range.
  3. Every other output happens. For any number {m:k != 0}, the input {m:x=2+frac(1, k)} gives {m:f(x)=k}.
  4. The range is {m:f(x) != 0}.

  2. A square root is never negative, so every output is at least 0.

3. Composite functions

You can apply one function and then another. The result is a {term:composite-function|composite function}. If g is applied first and then f, you write {m:fg(x)}, which means {m:f(g(x))}. You read it from the right: the function next to x goes first.

Key idea: {m:fg(x)} means {m:f(g(x))}. Apply g first, then f. The order matters.

  • {m:fg(x)=f(g(x))}: put {m:g(x)} into f. And {m:gf(x)=g(f(x))}: put {m:f(x)} into g. In general {m:fg(x)} and {m:gf(x)} are different functions.
  • {m:ff(x)=f(f(x))}: apply f twice.
  • For {m:fg(x)} to exist, x must be in the domain of g, and {m:g(x)} must be in the domain of f.
  • To solve {m:fg(x)=k}, first write {m:fg(x)} as an expression in x, then solve the equation.

Worked example: composite functions at a number

The functions f and g are given by {m:f(x)=x^2} and {m:g(x)=3x-1}. Find {m:fg(2)} and {m:gf(2)}.

  1. For {m:fg(2)}, apply g first: {m:g(2)=3*2-1=5}. Then apply f: {m:f(5)=5^2=25}.
  2. For {m:gf(2)}, apply f first: {m:f(2)=2^2=4}. Then apply g: {m:g(4)=3*4-1=11}.
  3. So {m:fg(2)=25} and {m:gf(2)=11}. They are different, so the order matters.

4. Inverse functions

An {term:inverse-function|inverse function} undoes a function. If {m:f(2)=7} then {m:f^(-1)(7)=2}. The inverse is written {m:f^(-1)} and read “f inverse”. Putting an input through f and then through {m:f^(-1)} gives the input back: {m:f^(-1)(f(x))=x}. And in the other order, {m:f(f^(-1)(x))=x}.

6. Functions in modelling

A function can be a model: a rule that describes a real situation. A model is not the real thing. It works for some inputs and not for others, and its outputs are only as good as its assumptions. Four questions help you to use a model well.

What inputs make sense? That is the domain, and the situation decides it. What outputs can it give? That is the range. Which input gives a particular output? That is an inverse. Where does the model stop being sensible? That is a limit of the model, and a better model can remove it.

Key idea: in a model, the domain comes from the situation, and the limits of the model are found from the range and from what the function does for large inputs.

  • Domain: use the situation, not only the formula. A time cannot be negative, so {m:t >= 0}. A count of items is a whole number.
  • Range: the outputs the model can give. A value that the model never reaches is not in the range.
  • A {term:limiting-value} is the level the output gets close to for very large inputs. On a graph it is a horizontal asymptote. The model may never reach it.
  • To refine a model, change the function so that an unrealistic prediction is removed, and say what you changed and why. A refined model is still only a model.
  • A composite function joins two models, when the output of the first is the input of the second. An inverse answers “what input gives this output?”.

So far you have put an input into a function and read off the output. Now go the other way. Start with the output, and find the input. And start with a composite function, and find the two functions inside it.

Forwards

From an input to an output: put the input into the formula.

Backwards

From an output to an input: solve {m:f(x)=k}. If f is many-to-one, there may be more than one input. The domain says which ones count.

Why it works

  • A function is a rule with no choices. Each input gives one output, so you can always say what {m:f(x)} is. That is why a mapping with two outputs for one input is not a function. Many inputs may share an output, because the rule does not have to be reversible.
  • The domain and range come from the rule. The formula decides which inputs break it: dividing by 0, the root of a negative number, the logarithm of a number that is not positive. The range is whatever the rule gives for the allowed inputs, so changing the domain can change the range.
  • The order in {m:fg(x)} is the order of the brackets. {m:f(g(x))} has g inside, and you work from the inside out. That is why the function next to x goes first.
  • An inverse needs a one-to-one function. To undo f you must be able to read the input back from the output. If two inputs gave the same output, you could not. A restricted domain removes the repeats.
  • The graph of an inverse is a reflection in {m:y=x}. The point {m:(a, b)} is on the graph of f when {m:f(a)=b}. That is the same as {m:f^(-1)(b)=a}, so {m:(b, a)} is on the graph of {m:f^(-1)}. Swapping the two coordinates of every point is a reflection in the line {m:y=x}.
  • A strictly increasing function meets its inverse only on y = x. Suppose {m:f(x)=f^(-1)(x)=y}. Then {m:f(x)=y} and {m:f(y)=x}. If {m:x < y}, an increasing f gives {m:f(x) < f(y)}, which says {m:y < x}. That is impossible. The case {m:x > y} fails the same way. So {m:x=y}.
  • A model is a function chosen for a purpose. Its domain is chosen from the situation, its range is what it can predict, and its limits show where it stops being believable. Refining a model changes the function, not the situation.

Common traps

  • Writing a domain with y, or a range with x. The domain is a set of inputs, so it is written with x. The range is a set of outputs, so it is written with {m:f(x)}.
  • Forgetting that the root of 0 is allowed: {m:sqrt(x-3)} has domain {m:x >= 3}, not {m:x > 3}.
  • Reading {m:fg(x)} as “f first”. The function next to x goes first.
  • Expanding {m:(2x+1)^2} as {m:4x^2+1}. The middle term {m:4x} is missing.
  • Treating {m:f^(-1)(x)} as {m:frac(1, f(x))}. The small {m:-1} marks an inverse, not a power.
  • Finding an inverse of a many-to-one function without restricting the domain, such as taking the inverse of {m:x^2} for all real x.
  • Taking both roots when the domain allows only one. For {m:x >= 2}, only the root with {m:x-2 >= 0} fits.
  • Giving the domain of {m:f^(-1)} as the domain of f. It is the range of f.
  • Forgetting that a composite function may have a smaller domain than the inner function: the output of g must be in the domain of f.
  • Drawing a graph and its inverse with different scales on the two axes. The reflection in {m:y=x} then looks wrong.
